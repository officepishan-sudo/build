# מדריך הידע — מקור הנתונים של סוכן ה-AI

זהו הקובץ הראשי של בסיס הידע. הסוכן שמוטמע בשרת קורא ממנו כדי לענות למשתמש
על שאלות מקצועיות בזמן תכנון וניהול הפרויקט ("כמה עולה ריצוף?", "מה חייב
להופיע במפרט של פרגולה?", "מה בודקים כשמגיע הדק?").

הקובץ הזה מגדיר **איך** בסיס הידע בנוי ואיך הסוכן מתנהג. התוכן עצמו יושב
בקבצי נושא נפרדים תחת `topics/`, קובץ לכל נושא.

> **למה לא הכל בקובץ אחד**: בסיס ידע מלא לפי האינדקס למטה הוא סדר גודל של
> 60 נושאים. בקובץ אחד זה בלתי ניתן לתחזוקה, ובעיקר — הסוכן יצטרך לטעון הכל
> לכל שאלה. הפיצול מאפשר לשלוף רק את הנושא הרלוונטי. הקובץ הזה הוא נקודת
> הכניסה היחידה: ממנו הסוכן מגיע לכל השאר.

---

## 1. איך הסוכן משתמש בקבצים

1. הסוכן מזהה נושא מתוך שאלת המשתמש לפי `title` ו-`aliases` שבראש כל קובץ נושא.
2. הוא טוען את קובץ הנושא המתאים (ואת הנושאים שב-`related` אם צריך).
3. הוא עונה מתוך הקובץ בלבד.

### כללי מענה מחייבים

| כלל | פירוט |
|---|---|
| **לא להמציא** | אם התשובה לא בקובץ — להגיד "אין לי את זה במדריך" ולהציע לשאול בעל מקצוע. אף פעם לא לנחש מחיר, תקן, או משך זמן. |
| **מחיר תמיד כטווח** | כל מחיר מוצג כטווח, עם היחידה, עם תאריך העדכון (`last_reviewed`), ועם המשפט: "טווח אינדיקטיבי — המחיר בפועל נקבע בהצעת מחיר". |
| **`confidence: low` או `price_basis: indicative`** | חייב להיאמר למשתמש במפורש שהנתון לא מאומת. |
| **בטיחות וקונסטרוקציה** | כל נושא עם `safety_critical: true` (קירות בטון, יציקות גג, מעקים) מלווה תמיד במשפט: "אינו ייעוץ הנדסי — נדרש מהנדס קונסטרוקציה". |
| **רגולציה** | כל אזכור היתר/תקן מלווה במשפט: "אינו ייעוץ משפטי — יש לאמת מול הרשות המקומית". תואם DEC-06. |
| **הפניה לאפליקציה** | כשיש מסך רלוונטי, להפנות אליו: "אפשר להוסיף את זה לכתב הכמויות". ראו `maps_to` בכל נושא. |
| **קיצור** | תשובה ראשונה = `## בקצרה` בלבד. פירוט רק אם המשתמש ביקש. |

### הקשר לאפליקציה

לפי DEC-01 אין אינטגרציה חיצונית למחירים — כל הנתונים מוזנים ידנית. המדריך
הזה הוא המקור הידני היחיד, ולכן הוא גם מזין ישירות ישויות באפליקציה. השדה
`maps_to` בכל נושא אומר לאילו:

| ערך ב-`maps_to` | מה הסוכן יכול להציע |
|---|---|
| `QuantityItem` | שורות מוכנות לכתב הכמויות (תיאור, יחידה, אופן חישוב הכמות) |
| `Alternative` | חלופות להשוואה במסך החלופות, עם יתרונות/חסרונות/טווח מחיר |
| `QuoteRequest` | סעיפי מפרט לבקשת הצעת מחיר, כדי שההצעות יהיו בנות-השוואה |
| `Defect` / `Issue` | רשימת בדיקות קבלה שהופכת לסעיפי ליקויים |
| `Warranty` / `MaintenanceItem` | תקופות אחריות ומשימות תחזוקה |
| `Professional` | סוג בעל המקצוע והרישוי הנדרש |
| `RegulatoryChecklistItem` | סעיפים לרשימת הבדיקה הרגולטורית |
| `Task` / `Phase` | מיקום בלוח הזמנים ותלויות בין שלבים |

## 2. מפרט קובץ נושא

כל קובץ ב-`topics/` נפתח ב-frontmatter ואחריו סעיפים בכותרות קבועות.
`topics/_TEMPLATE.md` הוא השלד להעתקה.

### Frontmatter

```yaml
---
id: flooring-tiles          # חובה. מזהה יציב, אנגלית, kebab-case. לא משתנה לעולם.
title: ריצוף                 # חובה. השם בעברית כפי שהמשתמש קורא לזה.
aliases: [אריחים, קרמיקה]    # חובה. כל מילה שהמשתמש עשוי לכתוב. זה מנוע החיפוש.
category: finishes          # חובה. structure|envelope|systems|finishes|outdoor|cross
phase: גמר                   # חובה. השלב בפרויקט.
status: published           # חובה. draft|review|published — הסוכן מגיש רק published.
confidence: medium          # חובה. high|medium|low — עד כמה התוכן מאומת.
price_basis: indicative     # חובה. indicative|verified — האם המחירים נבדקו מול השוק.
safety_critical: false      # חובה. true = חייב דיסקליימר הנדסי בכל תשובה.
last_reviewed: 2026-09-18   # חובה. תאריך מלא. הסוכן מציג אותו ליד מחירים.
related: [screed, grout]    # מזהי נושאים קשורים.
maps_to: [QuantityItem]     # ישויות באפליקציה שהנושא מזין.
---
```

### סעיפים

| סעיף | חובה | למה הוא שם |
|---|---|---|
| `## בקצרה` | ✔ | 2–4 שורות. זו התשובה הראשונה שהסוכן מחזיר. |
| `## מתי בפרויקט` | ✔ | שלב, מה חייב להיגמר לפני, מה חוסם אחרי. מזין לוח זמנים. |
| `## חלופות` | ✔ | טבלה: חלופה, יתרונות, חסרונות, טווח מחיר, למי מתאים. |
| `## כמויות ויחידות` | ✔ | יחידת המידה, איך מודדים, אחוז פחת. בלי זה אין כתב כמויות. |
| `## מה מרכיב את המחיר` | ✔ | פירוק לחומר / עבודה / הובלה — בדיוק שלושת השדות בכתב הכמויות. |
| `## טווחי מחיר` |  | טבלה. מסומן `indicative` עד שאומת. |
| `## מה חייב להופיע במפרט` | ✔ | הסעיף החשוב ביותר. בלעדיו הצעות מחיר לא ברות-השוואה. |
| `## שאלות לשאול` |  | מה לשאול את הקבלן/ספק לפני חתימה. |
| `## בעלי מקצוע` |  | איזה בעל מקצוע, איזה רישוי/הסמכה. |
| `## תקינה ורגולציה` |  | תקנים והיתרים. כל פריט מסומן `[לאימות]` עד שנבדק. |
| `## טעויות נפוצות ודגלים אדומים` | ✔ | מה משתבש בפועל ומה מסמן קבלן בעייתי. |
| `## בדיקות קבלה` | ✔ | מה בודקים ומתי. הופך ישירות לרשימת ליקויים. |
| `## אחריות ותחזוקה` |  | תקופת אחריות מקובלת ומשימות תחזוקה. |
| `## זמני אספקה` |  | כמה זמן להזמין מראש. |
| `## שאלות נפוצות` |  | זוגות שאלה/תשובה — יעד שליפה ישיר לסוכן. |

### כללי כתיבה

- מספר בלי יחידה הוא באג. תמיד `₪/מ"ר`, `ס"מ`, `ימי עבודה`.
- כל מספר שלא אומת נושא `[לאימות]` בשורה שלו.
- בלי שמות מותגים וספקים — התוכן מתיישן והאפליקציה לא ממליצה על ספק.
- מחירים ללא מע"מ, ומצוין שזה ללא מע"מ.

## 4. תחזוקה

- נושא שעבר שנה מ-`last_reviewed` — הסוכן מציין שהנתון ישן.
- מעבר `price_basis` ל-`verified` רק אחרי הצלבה מול הצעות מחיר אמיתיות
  שהתקבלו באפליקציה.
- `id` לא משתנה אחרי פרסום. לשינוי שם — לעדכן `title`, לא `id`.
